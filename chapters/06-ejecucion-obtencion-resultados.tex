\chapter{Ejecución y Obtención de Resultados}
\label{chap:ejecucion-obtencion-resultados}

\section{Entorno de desarrollo}

El sistema fue implementado en el lenguaje de programación Python, debido a su flexibilidad, amplia disponibilidad de librerías para optimización y manejo de datos, y su compatibilidad con métodos heurísticos y evolutivos. Para garantizar portabilidad y consistencia, se empleó un entorno virtual administrado mediante \texttt{venv}.

Las principales dependencias utilizadas fueron:

\begin{itemize}
    \item \textbf{NumPy}: manejo eficiente de arreglos y operaciones matemáticas.
    \item \textbf{Pandas}: construcción de estructuras tabulares para generar y almacenar instancias.
    \item \textbf{PyGAD}: librería empleada para la implementación del algoritmo genético.
    \item \textbf{Random}: generación de valores pseudoaleatorios para la creación de instancias.
\end{itemize}

El archivo \texttt{requirements.txt} incluye las versiones exactas utilizadas, permitiendo reproducir las condiciones de ejecución en cualquier sistema.

\section{Diseño del software}

El proyecto se estructuró siguiendo una arquitectura modular, organizada en tres componentes principales: generación de instancias, algoritmos de programación (AG y SPT) y simulación. Esto permite separar claramente la lógica del modelo del taller, los métodos de asignación y el procedimiento experimental.

\subsection{Arquitectura general del sistema}

A continuación se presentar la organización del software:

\begin{itemize}
    \item \textbf{config/}: contiene la configuración del taller y el generador de instancias.  
    \item \textbf{ag/}: módulo que implementa el algoritmo genético.  
    \item \textbf{spt/}: módulo con la implementación del método SPT.  
    \item \textbf{simulador.py}: orquesta la ejecución de instancias, aplicar ambos algoritmos y almacenar los resultados.  
\end{itemize}

Cada componente se comunica únicamente mediante estructuras de datos bien definidas, lo que facilita la extensibilidad y la validación del sistema.

\subsection{Flujo general del software}

El funcionamiento completo del sistema puede resumirse como:

\begin{enumerate}
    \item \textbf{Generación de instancias}: se construyen escenarios según la configuración del taller.
    \item \textbf{Ejecución de SPT y AG}: cada instancia se evalúa mediante ambos métodos.
    \item \textbf{Simulación operativa}: se usa la simulación formalizada en el Capítulo 4 para determinar las tareas aceptadas, rechazadas y métricas de desempeño.
    \item \textbf{Consolidación de resultados}: se almacenan métricas en archivos CSV para su análisis posterior.
\end{enumerate}

Este pipeline es consistente con el objetivo principal de la tesis: comparar el desempeño del algoritmo genético frente a un método clásico de ingeniería industrial.

\section{Implementación del algoritmo genético}

El módulo \texttt{ag/ag.py} implementa el algoritmo genético utilizando la librería PyGAD. El enfoque se basa en la representación dual del individuo, donde cada solución codifica simultáneamente la asignación de operarios y la prioridad de ejecución de cada tarea.

\subsection{Representación del individuo}

Dado un conjunto de tareas del día con tamaño $n$, se construye un cromosoma de longitud $2n$:

\[
\text{individuo} = [\, o_1,\dots,o_n,\; w_1,\dots,w_n \,]
\]

donde:

\begin{itemize}
    \item $o_i$ es el operario seleccionado para la tarea $i$.
    \item $w_i$ es un valor que representa la prioridad relativa de la tarea.
\end{itemize}

Esta representación permite modular tanto la asignación como la secuencia interna de ejecución.

\subsection{Generación del espacio de búsqueda}

El archivo \texttt{taller\_config.py} define, para cada tipo de tarea, qué operarios son aptos para ejecutarla. Esta información se utiliza para construir dinámicamente el \textit{gene space} del AG, restringiendo valores inválidos y reduciendo el espacio de búsqueda.

\subsection{Función de aptitud}

La función de aptitud está implementada de manera que evalúa cada individuo llamando al simulador operativo descrito en el Capítulo 4. El resultado final se obtiene mediante una métrica compuesta que penaliza:

\begin{itemize}
    \item Tareas rechazadas.
    \item Precedencias incumplidas.
    \item Exceso de carga.
\end{itemize}

Y recompensa:

\begin{itemize}
    \item Cantidad de tareas ejecutadas.
    \item Balance de carga entre operarios.
\end{itemize}

El pseudocódigo general de la evaluación es:

\begin{algorithm}[H]
\SetAlgoLined
Obtener asignación de operarios y prioridades desde el individuo\;
Construir ordenamiento de tareas según prioridades\;
Aplicar simulación operativa\;
Calcular métricas: ejecutadas, rechazadas, makespan, carga total, etc.\;
Combinar métricas en una aptitud final\;
\caption{Evaluación de un individuo mediante simulación operativa}
\end{algorithm}

\subsection{Integración con PyGAD}

El AG se ejecuta definiendo:
\begin{itemize}
    \item tamaño de población,
    \item número de generaciones,
    \item probabilidad de cruce,
    \item probabilidad de mutación.
\end{itemize}

PyGAD administra el proceso evolutivo, mientras que la evaluación real se realiza con el simulador del taller.

\subsection{Configuración base del algoritmo genético}
\label{subsec:configuracion-ag}

Antes de iniciar el proceso de calibración, se definió una configuración base del algoritmo genético que sirvió como punto de partida para todos los experimentos. Esta configuración incluye parámetros estándar recomendados en la literatura y valores validados empíricamente para garantizar un comportamiento estable del algoritmo.

\begin{itemize}
    \item Tamaño de población: 100 individuos
    \item Número de padres por generación: 10
    \item Padres preservados: 5
    \item Método de selección: \textit{rank}
    \item Operador de cruce: \textit{single\_point}
    \item Probabilidad de mutación: 15\%
    \item Tipo de mutación: \textit{random}
    \item Semilla aleatoria: 42
\end{itemize}

Esta configuración sirvió como referencia para evaluar de forma independiente cada parámetro crítico del algoritmo genético (operador de cruce, número de generaciones y probabilidad de mutación), tal como se detalla en las secciones siguientes.

\section{Implementación del método SPT}

El módulo \texttt{spt/spt.py} implementa la heurística Shortest Processing Time (SPT), adaptada al contexto del taller. La versión utilizada en esta tesis mantiene el espíritu del método clásico, pero incorpora restricciones reales del taller, como habilidades de operarios, repuestos y precedencias.

\subsection{Ordenamiento de tareas}

El método ordena las tareas según la duración:

\[
\text{orden SPT}: \quad p(tipo(i_1)) \le p(tipo(i_2)) \le \dots
\]

Este orden se ajusta automáticamente según precedencias y recursos disponibles.

\subsection{Asignación de operarios y validación}

Para cada tarea ordenada, el método:

\begin{enumerate}
    \item identifica operarios aptos,
    \item selecciona aquel con menor carga acumulada,
    \item verifica disponibilidad de repuestos,
    \item evalúa posibles solapamientos dentro de la misma OT.
\end{enumerate}

Si la tarea no puede ejecutarse bajo las restricciones del taller, se marca como rechazada.

\section{Ejecución de simulaciones}

El archivo \texttt{simulador.py} ejecuta el experimento completo. Para cada instancia generada, se aplican consecutivamente el método SPT y el algoritmo genético, almacenando métricas clave que permitirán una comparación justa.

\subsection{Generación de conjuntos de instancias}

Las instancias se generan con el módulo \texttt{generador\_instancias.py}, que permite configurar:

\begin{itemize}
    \item número mínimo y máximo de órdenes,
    \item número total de tareas,
    \item distribución de tipos,
    \item disponibilidad de repuestos.
\end{itemize}

\subsection{Ejecución conjunta de SPT y AG}

Para cada instancia:

\begin{enumerate}
    \item se ejecuta SPT y se registra su desempeño,
    \item se ejecuta el AG y se obtiene el mejor individuo,
    \item ambos resultados se evalúan con el simulador,
    \item se registran métricas comparables.
\end{enumerate}

\subsection{Consolidación de resultados}

Los datos generados por cada ejecución se almacenan en un archivo CSV, que posteriormente es utilizado en el Capítulo 7 para el análisis cuantitativo.

\subsection{Reproducibilidad}

Para garantizar repetibilidad, se fijan semillas aleatorias y se documentan los parámetros utilizados en cada corrida experimental.

\subsection{Evaluación del Operador de Cruce}
\label{subsec:cruce}

Con el objetivo de determinar el operador de cruce más adecuado para el algoritmo genético, se llevó a cabo un experimento comparativo empleando los dos operadores disponibles en la librería \texttt{PyGAD} que preservan parcialmente la estructura del individuo: \textit{single\_point} y \textit{two\_points}. Ambos operadores fueron evaluados bajo exactamente las mismas condiciones: misma población, mismas instancias, misma semilla aleatoria y la configuración base descrita en la Sección~\ref{subsec:configuracion-ag}.

El experimento se ejecutó sobre un conjunto de veinte instancias independientes, todas simuladas bajo un horizonte operativo de 480 minutos (equivalente a una jornada laboral completa). Este horizonte amplio permite observar diferencias reales en el comportamiento evolutivo; horizontes más cortos generan dinámicas artificialmente similares y no son adecuados para la calibración del algoritmo genético.

Los resultados evidencian diferencias consistentes entre los dos operadores evaluados. En promedio, \textit{single\_point} logra programar 1.65 tareas adicionales por instancia y utiliza de manera más intensiva el tiempo disponible de los operarios, lo cual es crítico dado que el objetivo principal del sistema es maximizar la cantidad de trabajo completado durante la jornada.

La mayor cantidad de tareas ejecutadas está alineada con la función de aptitud del AG, que prioriza explícitamente este criterio. El mejor comportamiento observado para \textit{single\_point} indica que este operador favorece combinaciones más estables entre asignación y prioridad, preservando estructuras útiles a lo largo del proceso evolutivo.

En conclusión, con base en la evidencia experimental, se seleccionó el operador \textit{single\_point} como el más adecuado y este fue utilizado en los experimentos posteriores del proceso de calibración del algoritmo genético.

\subsection{Evaluación del Número de Generaciones}
\label{subsec:generaciones}

Una vez seleccionado el operador de cruce \textit{single\_point}, el siguiente paso en la calibración del algoritmo genético consistió en determinar un número adecuado de generaciones. Este parámetro controla la profundidad de la búsqueda evolutiva y, por tanto, influye directamente en la calidad de las soluciones obtenidas y en el costo computacional del proceso.

Siguiendo recomendaciones comunes en la literatura sobre algoritmos genéticos, se evaluaron tres niveles de profundidad evolutiva: 300, 800 y 1300 generaciones. Estos valores representan una escala progresiva de exploración del espacio de búsqueda (baja, media y alta), permitiendo observar cómo varía el desempeño del AG a medida que se incrementa el esfuerzo evolutivo. Todas las ejecuciones conservaron la misma configuración base descrita en la Sección~\ref{subsec:configuracion-ag} y se aplicaron sobre veinte instancias independientes bajo un horizonte de programación de 480 minutos.

Este patrón sugiere que el AG converge rápidamente en el problema de programación del taller, y que extender el proceso evolutivo más allá de 300 generaciones no aporta beneficios relevantes en términos de calidad de solución. Considerando tanto el desempeño observado como la eficiencia computacional, se seleccionaron \textbf{300 generaciones} como valor óptimo para las siguientes etapas del proceso de calibración del algoritmo genético.

\subsection{Evaluación de la Probabilidad de Mutación}
\label{subsec:mutacion}

El último parámetro evaluado en el proceso de calibración del algoritmo genético corresponde a la probabilidad de mutación. Este parámetro controla el grado de exploración del espacio de búsqueda mediante modificaciones aleatorias en los genes del individuo. Una mutación demasiado baja puede conducir a una convergencia prematura, limitando la capacidad del algoritmo para escapar de soluciones subóptimas; por el contrario, una mutación excesiva puede introducir demasiada variabilidad y destruir estructuras útiles adquiridas durante el proceso evolutivo.

Siguiendo prácticas habituales en la literatura, se evaluaron tres niveles representativos de intensidad de mutación: 5\%, 15\% y 25\%. Estos valores permiten analizar la sensibilidad del AG frente a distintos grados de exploración aleatoria. Las ejecuciones conservaron la configuración base descrita en la Sección~\ref{subsec:configuracion-ag}, utilizando el operador de cruce previamente seleccionado y un horizonte operativo de 480 minutos. Cada configuración fue evaluada sobre veinte instancias independientes.

Los resultados revelan diferencias marcadas entre los niveles de mutación evaluados. Sin embargo, esta configuración también genera un mayor número de tareas rechazadas, lo que indica una mayor frecuencia de incumplimientos operativos.

En contraste, el nivel intermedio del 15\% obtiene la menor cantidad de tareas rechazadas y el makespan más bajo, evidenciando soluciones más estables y con menos violaciones a las restricciones del taller. Aunque ejecuta menos tareas que la configuración del 5\%, sus cronogramas son más consistentes y equilibrados.

Finalmente, una mutación más elevada (25\%) logra un desempeño intermedio en todas las métricas, reflejando un punto donde el aumento de aleatoriedad comienza a afectar la estabilidad evolutiva sin llegar a generar beneficios adicionales.

En conjunto, estos resultados muestran un compromiso entre maximizar tareas ejecutadas y mantener la factibilidad operativa. Dado que la función de aptitud prioriza la ejecución efectiva dentro de las restricciones, se seleccionó una probabilidad de mutación del \textbf{15\%} como valor óptimo para la configuración final del algoritmo genético, al ofrecer el mejor equilibrio entre exploración, estabilidad y cumplimiento operativo.

\section{Configuración Final del AG}

A partir del proceso de calibración presentado en las subsecciones anteriores ---donde se evaluaron de forma independiente el operador de cruce, el número de generaciones y la probabilidad de mutación--- se obtuvo una configuración final del algoritmo genético que equilibra de manera adecuada la calidad de las soluciones y el costo computacional. Esta configuración fue utilizada en todas las comparaciones realizadas posteriormente contra el método SPT en el Capítulo~7.

En síntesis, la calibración determinó que:

\begin{itemize}
    \item El operador de cruce \textit{single\_point} ofrece el mejor desempeño en un horizonte amplio de 480 minutos, superando consistentemente a \textit{two\_points}.
    \item Un número de \textbf{300 generaciones} es suficiente para que el algoritmo converja hacia soluciones de alta calidad, mientras que valores mayores no aportan mejoras significativas y pueden incluso degradar el rendimiento.
    \item Una probabilidad de mutación del \textbf{15\%} logra el mejor equilibrio entre exploración y explotación del espacio de búsqueda, evitando tanto la convergencia prematura (como sucede con 5\%) como la pérdida de estabilidad evolutiva (observada con 25\%).
\end{itemize}
