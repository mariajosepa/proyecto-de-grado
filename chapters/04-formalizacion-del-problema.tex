\chapter{Formalización del problema}

El presente capítulo describe la estructura formal del problema de programación diaria del taller industrial, incluyendo la caracterización del flujo operativo, la definición matemática de los elementos que componen el sistema y la modelación del comportamiento del taller bajo sus restricciones reales. Esta formalización constituye la base para el desarrollo posterior del algoritmo genético y el método SPT, presentados en los capítulos siguientes.

\section{Estudio del flujo de trabajo del taller industrial}

El taller de reparación de motores opera bajo un flujo secuencial condicionado por restricciones de precedencia, disponibilidad de repuestos, habilidades del personal e interacción entre tareas dentro de una misma orden de trabajo. Cada día se recibe un conjunto de órdenes de trabajo que agrupan tareas mecánicas con distintos requerimientos técnicos, y el objetivo operativo es completar la mayor cantidad posible de dichas tareas dentro de la jornada laboral.

\subsection{Tipos de tareas}

Sea \(T = \{1, \dots, q\}\) el conjunto de tipos de tareas que el taller está en capacidad de ejecutar.  
Cada tipo de tarea representa una operación específica dentro del proceso de reparación, cuya duración base está dada por una función:

\[
p : T \rightarrow \mathbb{N}
\]

que asigna a cada tipo \(t \in T\) su duración en minutos.

Las tareas concretas del día se representan mediante:

\[
T_d = \{1, \dots, n\},
\]

donde cada tarea \(i \in T_d\) posee los atributos:
\begin{itemize}
    \item \(ot(i)\): orden de trabajo a la que pertenece;
    \item \(tipo(i)\): tipo de tarea según \(T\);
    \item \(p(tipo(i))\): duración efectiva.
\end{itemize}

\subsection{Operarios y recursos disponibles}

Sea \(O = \{1, \dots, r\}\) el conjunto de operarios disponibles en el taller.  
Cada tarea requiere habilidades específicas, modeladas mediante:

\[
E(t) \subseteq O, \qquad \forall t \in T,
\]

donde \(E(t)\) es el conjunto de operarios aptos para ejecutar tareas del tipo \(t\).  
La aptitud del operario es una restricción estricta: una tarea no puede ser programada por un operario fuera de \(E(tipo(i))\).

\subsection{Reglas industriales de asignación}

El taller opera bajo restricciones naturales del proceso mecánico:

\begin{itemize}
    \item \textbf{Precedencias intrínsecas}: ciertas tareas deben completarse antes de que otras puedan iniciar.  
    Modelado mediante:
    \[
    P(t) \subseteq T,
    \]
    que representa los tipos de tarea que deben preceder al tipo \(t\).

    \item \textbf{Precedencias por orden de trabajo}: sólo son relevantes aquellas precedencias que ocurren dentro de la misma orden de trabajo.
    
    \item \textbf{Disponibilidad de repuestos}: cada orden de trabajo \(ot\) tiene asociado un vector binario:
    \[
    R_{ot} = (r_1, r_2, \dots), \quad r_j \in \{0,1\},
    \]
    donde \(r_j = 1\) indica que el repuesto necesario para cierto tipo de tarea está disponible.

    \item \textbf{Capacidad temporal}: cada operario posee un máximo de 8 horas de trabajo:
    \[
    H = 480 \text{ minutos}.
    \]
\end{itemize}

\subsection{Análisis del proceso actual y puntos críticos}

El proceso presenta dificultades estructurales:
\begin{itemize}
    \item Los operarios poseen habilidades heterogéneas.
    \item Las órdenes contienen dependencias internas que condicionan el flujo.
    \item Los repuestos no siempre están disponibles.
    \item El tiempo límite de jornada restringe la cantidad de tareas ejecutables.
    \item Tareas pertenecientes a una misma orden no pueden solaparse.
\end{itemize}

El resultado es un entorno altamente restrictivo donde la programación manual es compleja y propensa a tiempos improductivos.

\subsection{Flujo general del proceso}

Operativamente, el taller funciona bajo este flujo conceptual:

\begin{enumerate}
    \item Llegan varias órdenes de trabajo, cada una con un conjunto de tareas.  
    \item Cada tarea requiere un operario apto y, en algunos casos, un repuesto.  
    \item Algunas tareas dependen de otras dentro de la misma orden.  
    \item Los operarios ejecutan las tareas secuencialmente en una jornada limitada.  
    \item El objetivo es completar la mayor cantidad posible de tareas.
\end{enumerate}

Este flujo será simulado formalmente en la evaluación de soluciones.
\section{Modelación del Problema y Archivo de Configuración del Taller}

El archivo \texttt{taller\_config.py} es un módulo de configuración que centraliza toda la información estructural del taller requerida para la simulación y 
los algoritmos de asignación. Este archivo actúa como la representación formal del sistema productivo real y contiene los catálogos de tareas, las relaciones de precedencia, la clasificación de operarios, 
sus habilidades, la duración base de cada operación y las reglas operativas fundamentales. Fue construido a partir del levantamiento de información realizado con la empresa Recti-Ram, y sirve como la “fuente de verdad” sobre la cual el generador de 
instancias, el simulador, el algoritmo genético y el método SPT basan todas sus decisiones. De este modo, el archivo garantiza consistencia, reproducibilidad y correspondencia entre el modelo computacional y 
las condiciones reales del taller.

Para implementar y evaluar los algoritmos de asignación desarrollados en este trabajo, fue necesario construir una representación formal del funcionamiento real del taller. Esta modelación constituye un puente entre el dominio operativo del 
taller y los métodos computacionales descritos en capítulos posteriores. Con este fin, se diseñó un archivo de configuración denominado \texttt{taller\_config}, el cual consolida la estructura de tareas, las relaciones de precedencia, las habilidades de los operarios, 
la disponibilidad de repuestos, la duración base de las actividades y el horizonte de planificación diario. La construcción de este archivo se realizó en estrecha colaboración con la empresa aliada, Rectificadora Recti-Ram, garantizando que el modelo resultante reflejara de 
forma fiel las condiciones reales del proceso productivo.

\subsection{Clasificación de familias de tareas del taller}

El proceso completo de reparación de motores en un taller de rectificación se compone de múltiples operaciones que pueden agruparse en cuatro grandes familias, según la naturaleza mecánica y el componente del motor intervenido:

\begin{itemize}
    \item \textbf{Tareas de Bloque}: incluyen inspección, pruebas hidrostáticas, rectificación de cilindros, encamisado, glaseado y reconstrucción de bancadas. Estas actividades constituyen etapas intensivas en maquinaria pesada.
    \item \textbf{Tareas de Culata}: comprenden instalación y fabricación de guías, rectificación de válvulas, cepillado de culata, adaptación y reconstrucción de alojamientos. Son tareas que exigen precisión y una alta especialización del operario.
    \item \textbf{Tareas de Cigüeñal}: incluyen operaciones como metalizado, pulido, rectificación de muñones y balanceo del cigüeñal. Son procesos mecánicos especializados que requieren maquinaria específica.
    \item \textbf{Tareas de Bielas}: abarcan asentado, instalación de pistón y armado del conjunto biela--pistón.
\end{itemize}

El conjunto completo está compuesto por 35 tipos de tareas identificadas y validadas directamente con el taller, cada una asignada a una de estas cuatro familias.

\subsection{Distribución de frecuencia de tareas y estimación empírica}

Durante la fase de levantamiento de información, se revisaron las órdenes de trabajo típicas manejadas por Recti-Ram. Con base en esta revisión y en entrevistas con el personal técnico, se estimó la proporción mensual en que aparecen cada una de las familias de tareas. El resultado permitió establecer una distribución operativa que se utiliza posteriormente para la generación de instancias de prueba:

\begin{itemize}
    \item \textbf{60\% Culatas} -- debido a que la rectificación de culatas constituye la mayor demanda mensual.
    \item \textbf{20\% Bloque} -- tareas costosas en maquinaria pero menos frecuentes.
    \item \textbf{10\% Cigüeñal}.
    \item \textbf{10\% Bielas}.
\end{itemize}

Esta distribución no solo refleja el comportamiento real del taller, sino que también permite que las instancias generadas para entrenamiento y validación de los algoritmos sigan patrones realistas de demanda.

\subsection{Clasificación de operarios y habilidades técnicas}

La empresa cuenta con dos grupos principales de operarios:

\begin{itemize}
    \item \textbf{Operarios especializados en Bloque}: un grupo de 6 operarios entrenados para tareas de rectificación y mecanizado pesado.
    \item \textbf{Operarios especializados en Culata}: un grupo de 12 operarios capacitados en procesos de precisión asociados a la culata.
\end{itemize}

Ambos grupos poseen, además, habilidades parciales o complementarias para tareas de Cigüeñal y Bielas, lo que se refleja directamente en la matriz de aptitudes utilizada en el modelo (\texttt{OPERARIOS\_APTOS}). Cada operario cuenta con un subconjunto específico de tareas que puede ejecutar, lo cual introduce restricciones reales en la asignación y limita el espacio de búsqueda del algoritmo genético, obligándolo a considerar soluciones factibles desde el punto de vista operativo.

\subsection{Estructura del archivo de configuración}

El archivo \texttt{taller\_config} consolida todos los elementos requeridos para modelar el problema de programación de tareas. Sus componentes principales son:

\begin{itemize}
    \item \textbf{Catálogo de tareas} (\texttt{TAREAS}): relación de los 35 tipos de tareas clasificadas por familia.
    \item \textbf{Relaciones de precedencia} (\texttt{PRECEDENCIAS}): definidas con base en la secuencia técnica real del proceso de rectificación. Por ejemplo, en la familia Bloque, las operaciones siguen un orden altamente estructurado, desde inspección hasta pruebas finales.
    \item \textbf{Duraciones base} (\texttt{DURACIONES\_BASE}): representan tiempos promedio estimados por operarios expertos. Posteriormente, durante la generación de instancias, estas duraciones se someten a una variabilidad controlada del 10\% para simular condiciones reales.
    \item \textbf{Operarios y aptitudes} (\texttt{OPERARIOS} y \texttt{OPERARIOS\_APTOS}): definen las habilidades individuales de cada operario y las tareas que puede ejecutar.
    \item \textbf{Horizonte diario} (\texttt{HORIZONTE}): fijado en 480 minutos, correspondiente a la jornada laboral de 8 horas.
    \item \textbf{Disponibilidad de repuestos} (\texttt{repuestos\_por\_ot}): representa la existencia o ausencia de insumos para tareas de una misma orden de trabajo.
\end{itemize}

La combinación de estos elementos permite que tanto el algoritmo genético como el método SPT operen sobre un entorno controlado, reproducible y altamente representativo del funcionamiento real del taller.

\subsection{Uso de la modelación en la generación de instancias}

A partir de esta configuración se diseñó un generador de instancias capaz de simular días completos de operación. El generador:

\begin{enumerate}
    \item Selecciona aleatoriamente un número de órdenes de trabajo.
    \item Asigna tareas a cada orden siguiendo la estructura de precedencias.
    \item Respeta la distribución empírica (60--20--10--10) para seleccionar familias de tareas.
    \item Aplica variabilidad a las duraciones para simular condiciones reales.
    \item Genera aleatoriamente la disponibilidad de repuestos con una probabilidad configurable de escasez.
\end{enumerate}

Este procedimiento permite evaluar el rendimiento de los algoritmos desarrollados en escenarios variados y realistas, asegurando que los resultados obtenidos sean representativos de las condiciones de producción del taller.

\section{Diseño del modelo de datos para la simulación}

\subsection{Conjuntos y parámetros del sistema}

El problema se formaliza mediante los siguientes conjuntos:

\[
\begin{aligned}
OT &= \{1, \dots, m\} && \text{Órdenes de trabajo},\\
T_d &= \{1, \dots, n\} && \text{Tareas del día},\\
O &= \{1, \dots, r\} && \text{Operarios},\\
T &= \{1, \dots, q\} && \text{Tipos de tarea}.
\end{aligned}
\]

Parámetros principales:

\[
\begin{aligned}
p(t) & && \text{Duración del tipo de tarea } t,\\
E(t) &\subseteq O && \text{Operarios aptos},\\
P(t) &\subseteq T && \text{Precedencias por tipo},\\
R_{ot} & && \text{Vector de disponibilidad de repuestos para la OT},\\
H &= 480 && \text{Horizonte máximo diario}.
\end{aligned}
\]

\subsection{Variables del modelo}

Durante la simulación se manejan variables que representan el estado del taller:

\[
\begin{aligned}
tpo[o] &: \text{ tiempo utilizado por el operario } o,\\
comp[ot] &: \text{ tipos de tareas ya completadas en la OT},\\
occ[ot] &: \text{ intervalos ocupados por la OT}.
\end{aligned}
\]

\subsection{Representación de operarios, tareas y repuestos}

\begin{itemize}
    \item Las tareas se representan por su índice \(i\) y atributos: tipo, orden y duración.
    \item Un operario sólo puede ejecutar tareas cuyos tipos estén en \(E(t)\).
    \item Los repuestos se representan mediante el vector binario \(R_{ot}\).
\end{itemize}

\subsection{Tiempos de operación y estructura temporal}

El tiempo se representa en minutos dentro del intervalo \([0, H]\).  
Una tarea \(i\) ejecutada por un operario \(o\) genera un intervalo:

\[
[s_i, f_i) = [tpo[o],\ tpo[o] + p(tipo(i))).
\]

\subsection{Restricciones formales del taller}

Una tarea \(i\) puede ejecutarse si y sólo si:

\[
\begin{array}{rl}
\text{(1)}\; o \in E(tipo(i)) 
    & \text{Aptitud del operario,} \\[6pt]

\text{(2)}\; R_{ot(i)} \text{ provee repuesto disponible} 
    & \text{Repuesto disponible,} \\[6pt]

\text{(3)}\; P(tipo(i)) \cap T_{ot(i)} \subseteq comp[ot(i)] 
    & \text{Precedencias cumplidas,} \\[6pt]

\text{(4)}\; f_i \le H 
    & \text{No excede jornada,} \\[6pt]

\text{(5)}\; [s_i, f_i) \cap occ[ot(i)] = \emptyset 
    & \begin{array}{l}
        \text{No solapa con} \\
        \text{tareas de la misma OT.}
      \end{array}
\end{array}
\]

\section{Construcción del generador de instancias}

\subsection{Parámetros de la simulación y alcance}

Cada día se genera una instancia compuesta por:
\begin{itemize}
    \item Un conjunto de órdenes.
    \item Un conjunto de tareas concretas.
    \item Habilidades del personal.
    \item Duraciones de tareas.
    \item Precedencias.
    \item Repuestos disponibles.
\end{itemize}

\subsection{Modelo de aleatoriedad y distribución de tiempos}

El generador recibe:
\begin{itemize}
    \item El número de órdenes,
    \item El número de tareas por orden,
    \item Su distribución temporal (según \(p(t)\)),
    \item Disponibilidad de repuestos,
    \item Habilidades por tipo.
\end{itemize}

\subsection{Procedimiento de creación de escenarios}

El proceso consiste en:

\begin{enumerate}
    \item Seleccionar órdenes y sus tareas.  
    \item Asignar tipos y duraciones.  
    \item Generar disponibilidad de repuestos.  
    \item Asignar operarios aptos por tipo.  
    \item Construir la instancia final \((OT, T_d, O)\).
\end{enumerate}

\subsection{Validación del modelo simulado con expertos}

Los parámetros fueron validados con personal del taller, asegurando que:
\begin{itemize}
    \item Las duraciones son realistas.
    \item Las precedencias corresponden al flujo mecánico real.
    \item Las habilidades reflejan la estructura del personal.
    \item El horizonte de 8 horas es consistente con el turno laboral.
\end{itemize}

\subsection{Pseudocódigo del simulador operativo}

El corazón de la simulación consiste en determinar si una asignación propuesta es válida.  
El pseudocódigo siguiente refleja el comportamiento operativo del taller:

\begin{algorithm}[H]
\SetAlgoLined
Inicializar estructuras: $tpo[o] \leftarrow 0$, $comp[ot] \leftarrow \emptyset$, $occ[ot] \leftarrow \emptyset$\;
\ForEach{operario $o \in O$}{
    Obtener conjunto de tareas asignadas $T_o$\;
    Ordenar $T_o$ según prioridad descendente\;
    \ForEach{tarea $i \in T_o$}{
        Verificar aptitud: $o \in E(tipo(i))$\;
        Verificar repuesto disponible\;
        Verificar precedencias cumplidas en $comp[ot(i)]$\;
        Calcular intervalo $[s_i,f_i) = [tpo[o], tpo[o] + p(tipo(i))]$\;
        \If{$f_i > H$}{rechazar tarea; continuar}
        \If{$[s_i,f_i)$ solapa con algún intervalo en $occ[ot(i)]$}{rechazar tarea; continuar}
        Aceptar tarea: actualizar $tpo[o]$, $comp$, $occ$\;
    }
}
\caption{Simulación operativa de programación de tareas}
\end{algorithm}
